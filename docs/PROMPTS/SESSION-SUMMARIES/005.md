## Summary

Focused entirely on getting MCP working correctly across Claude Code and Cursor, then building a polished install experience for new users.

Started by debugging why the MCP server wasn't appearing in Claude Code's `/mcp` list despite the config being in `~/.claude/settings.json`. Discovered that Claude Code doesn't read `mcpServers` from settings.json — it uses `.mcp.json` at the project root for project-level, and `claude mcp add --scope user` (writes to `~/.claude.json`) for global. Got both working. Cursor uses `.cursor/mcp.json`.

Updated the setup page with correct installation instructions for both clients, including the CLI command for Claude Code and the `.cursor/mcp.json` approach for Cursor. Also surfaced the skill file content directly on the setup page (users won't have repo access in production).

Consolidated the skill files — one universal format with YAML frontmatter works for both Claude Code and Cursor, just installed to different locations. Restructured to `skills/lorekeeper-advisor/SKILL.md` directory format per Claude Code best practices.

Built an interactive install script (`scripts/install.sh`) served at `/setup/install` — ASCII art banner, client selection (Claude Code/Cursor), scope selection (global/local), MCP setup, skill file download, and a start script that launches the advisor session. Fixed the `curl | bash` stdin issue (`read` from `/dev/tty`).

Also fixed the easter egg page at `/lorekeeper` which was double-wrapping in the layout.

## Decisions

- **MCP config**: Global Claude Code via `claude mcp add --scope user`, project-level via `.mcp.json`. Cursor via `.cursor/mcp.json`.
- **One skill file**: Universal format, different install paths per client.
- **Skill structure**: `skills/lorekeeper-advisor/SKILL.md` with YAML frontmatter (`name`, `description`, `when_to_use`).
- **HTTP over stdio**: Prioritize URL transport for MCP — simpler, works across clients.
- **Install script**: Interactive bash with `/dev/tty` reads, ASCII-only output, served from the running server.

## Insights

- Claude Code MCP config is **not** in `settings.json` — that's a common misconception. The CLI command is the canonical way.
- `curl | bash` scripts need `read < /dev/tty` since stdin is the curl stream.
- Cursor skill files and Claude Code skill files use the same YAML frontmatter format — the format is universal.
- The `{ layout: false }` third arg to `reply.view()` in `@fastify/view` doesn't work as expected — render manually with `Handlebars.compile()` for layout-free pages.
