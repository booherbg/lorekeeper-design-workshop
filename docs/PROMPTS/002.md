# Checkpoint Log — Session 002

## 1. Testing Strategy Design

> Let's create some reasonable testing specs that won't get in our way but gives us a great chance at getting this thing right — I want to be able to set you up on this overnight and wake up to a full implementation.

Designed two-layer testing strategy: service layer tests (workhorse) + lightweight web route smoke tests. No E2E. Real SQLite, no mocks. Vitest with `.inject()`. Created `docs/SPECS/testing.md`.

## 2. No E2E Testing

> Should we spin up end to end testing to make sure we aren't missing anything too wild?

Decided against it. Playwright adds dependency complexity and flakiness that kills unattended runs. `.inject()` already hits the full stack. E2E remains a stretch goal.

## 3. Overnight Run Hardening

> What else should we account for so that we have the best odds of success?

Identified six failure modes: spec ambiguity, migration drift, TS import errors, port conflicts, template rendering crashes, method override complexity. Added concrete mitigations to the testing spec.

## 4. Drop JSON API Routes

> Who uses the API routes? Is that different from MCP?

Realized JSON API routes are redundant — MCP tools call the service layer directly. Removed all `/api/*` routes. Restructured tests around service layer (contract tests for both web and MCP) instead of HTTP/JSON integration tests.

## 5. POST for Web Mutations

> What's idiomatic? Fastify certainly has a pattern for this.

No established Fastify method-override pattern. Went with POST for all web mutations (`/update`, `/delete` suffixes). API-style PUT/DELETE only in MCP. Updated all route tables in api-endpoints spec.
